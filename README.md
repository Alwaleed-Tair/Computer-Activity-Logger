# Computer Activity Logger

برنامج **Bash** يعمل في الخلفية على Linux، وبموافقة صريحة من المستخدم، ويسجّل:

- اسم المستخدم ووقت بداية ونهاية كل **جلسة استخدام**.
- كل **عملية** تبدأ أو تنتهي (اسمها فقط)، مع وقت البدء والانتهاء والمدة.

ثم يحوّل ذلك إلى **إحصائيات** و**تقارير CSV** تُفتح مباشرة في Microsoft Excel.

> الحالة: **v0.6 — التشغيل التلقائي (خدمة systemd للمستخدم) مكتمل** فوق Report Generator (تقارير Session / Application Activity / Usage Summary يومية وبفترة، بكتابة ذرّية وحماية للتاريخ) فوق Activity Analyzer وProcess Monitor وSession Logger.
> التصميم الكامل في [`docs/DESIGN.md`](docs/DESIGN.md).

## الخصوصية (ملتزمون بها)

| يُسجَّل | لا يُسجَّل أبدًا |
|---|---|
| اسم العملية، وقت البدء/الانتهاء، المدة | ضغطات المفاتيح، كلمات المرور، الحافظة |
| اسم المستخدم الحالي فقط | وسائط سطر الأوامر (قد تحوي أسرارًا) |
| بداية/نهاية الجلسة | عناوين النوافذ، محتوى الشاشة أو الملفات |
| | أي شيء عن مستخدمين آخرين، أو أي اتصال بالشبكة |

لا يعمل البرنامج قبل موافقتك الصريحة، ويمكنك في أي وقت: `status` · `stop` · `consent --revoke` · `purge --all`.

## المتطلبات

Bash ≥ 4.3 وأدوات Linux القياسية: `ps awk sort cut head flock df date`
(اختياريًا: `column` لتنسيق الجداول، `systemctl` و`systemd-notify` للتشغيل التلقائي). للتحقق: `./main.sh doctor`

## التشغيل السريع

```bash
./main.sh consent        # اقرأ الإشعار واكتب yes للموافقة
./main.sh start          # يبدأ في الخلفية
./main.sh status         # الحالة والمسارات وحجم البيانات
./main.sh stats          # تقرير النشاط الكامل في الطرفية (أضف --utc-offset +03:00 لحدود اليوم المحلية)
./main.sh report         # تقرير الفترة كاملة → reports/period/UTC/all/   (راجع «مولّد التقارير»)
./main.sh sessions       # سجل الجلسات (UTC) — أضف --local أو --tz Asia/Riyadh للتوقيت المحلي
./main.sh processes      # آخر العمليات المنتهية — أضف --running (الجارية الآن) أو --apps أو --background أو --check
./main.sh stop           # يوقف ويحفظ كل السجلات المفتوحة (إن لم يستجب خلال STOP_TIMEOUT_SEC يُفرض إيقافه ويُغلق التعافي جلسته عند التشغيل التالي)
```

خيارات مفيدة: `stats --from 2026-10-01 --to 2026-10-31 --top 5` ·
`INTERVAL_SEC=2 ./main.sh start` · `./main.sh purge --before 2026-01-01`.

## التشغيل التلقائي عند تسجيل الدخول (systemd user service)

خدمة **على مستوى المستخدم** (`systemctl --user`): تعمل بصلاحياتك أنت فقط، **بلا root ولا sudo**، ومعلنة وظاهرة لك: `systemctl --user list-units`، وأوامر `./main.sh service …` أدناه، وسجل أخطائها في ملف مستقل. لا شيء يعمل مخفيًا ولا قبل موافقتك.

### ⚠️ تسجيل الدخول ليس تشغيل الجهاز

| اللحظة | ما الذي يبدأ عندها |
|---|---|
| **إقلاع الجهاز (boot)** | لا تبدأ خدمات المستخدم (إلا إن فعّلت *lingering*، انظر أدناه) |
| **أول تسجيل دخول لك** (شاشة، TTY أو SSH) | يشغّل systemd *مدير المستخدم* (`systemd --user`) ثم يشغّل خدمتنا |
| **آخر تسجيل خروج لك** | يوقف systemd مدير المستخدم فتُوقَف الخدمة بأمان (تُحفظ الجلسة) |

لذلك `Login_Time` في `sessions.csv` هو لحظة **بدء المسجّل** (دخولك)، وقد يتأخر ساعات عن إقلاع الجهاز، ولا يُعدّ لحظة تشغيل الجهاز. يعرض `./main.sh service status` الاثنين معًا: «Machine boot» (من `/proc/stat`) و«Starts at». دخول SSH ثانٍ أو تبديل المستخدم السريع لا يبدأ نسخة ثانية (انظر «نسخة واحدة فقط»). لتبدأ الخدمة مع الإقلاع دون دخولك: `loginctl enable-linger "$USER"` (اختياري، وحينها تُسجَّل جلسة منذ الإقلاع حتى لو لم تدخل — فكّر في ذلك قبل تفعيله؛ ولإلغائه `loginctl disable-linger "$USER"`).

الحد الأدنى: Ubuntu 20.04+ (systemd ≥ 240 لدعم `StandardError=append:`؛ وUbuntu 24.04 فيها 255).

### التثبيت (Installation)

```bash
git clone <repo> && cd Computer-Activity-Logger
./main.sh doctor              # فحص البيئة (يذكر إن كان مدير systemd للمستخدم متاحًا)
./main.sh consent             # اقرأ الإشعار واكتب yes — بدون موافقة مسجّلة لا يعمل شيء
./main.sh service install     # يكتب ~/.config/systemd/user/cal.service (لا يفعّل ولا يشغّل)
```

أو دفعة واحدة (موافقة + تثبيت + تفعيل + تشغيل): `install/install.sh` (أضف `--accept` لتخطي السؤال، و`--with-daily-reports` لمؤقّت التقارير اليومية). `./main.sh service show-unit` يطبع ملف الوحدة قبل التثبيت لتراجعه.

### التفعيل (Enable Service) — يبدأ عند كل تسجيل دخول

```bash
./main.sh service enable      # ≈ systemctl --user enable cal.service
./main.sh service disable     # لإيقاف البدء التلقائي (لا يوقف النسخة العاملة)
```

### التشغيل (Start Service)

```bash
./main.sh service start       # ≈ systemctl --user start cal.service
```

يرجع بنجاح فقط حين يكون المسجّل **يسجّل فعلًا** (`Type=notify`: لا يُعلن الجاهزية إلا بعد فتح الجلسة). وإلا يطبع سبب الفشل وآخر أسطر سجل الأخطاء.

### الإيقاف (Stop Service) — آمن

```bash
./main.sh service stop        # ≈ systemctl --user stop cal.service
```

يرسل `SIGTERM` فيُغلق المسجّل الجلسة المفتوحة (`COMPLETED`) وكل العمليات المتتبَّعة (`SESSION_END`)، ويكتب الصفوف ويحرّر القفل ثم يخرج (عادةً أقل من ثانية). إن لم ينتهِ خلال `STOP_TIMEOUT_SEC + 5` ثوانٍ يُقتل، وعند التشغيل التالي يغلق التعافي الجلسة (`CRASHED`) فلا يضيع شيء.

### إعادة التشغيل (Restart Service)

```bash
./main.sh service restart     # يحفظ ويغلق الجلسة الحالية ثم تبدأ جلسة جديدة
```

### حالة الخدمة (Check Service Status)

```bash
./main.sh service status      # رمز الخروج: 0 تعمل · 3 مثبّتة لكنها متوقفة · 4 غير مثبّتة/لا مدير systemd
./main.sh service logs 50     # سجل الأخطاء المستقل + journal
systemctl --user status cal.service      # الأمر الأصلي نفسه
```

يعرض: ملف الوحدة، مفعّلة أم لا، الحالة ومنذ متى، PID، عدد إعادات التشغيل التلقائية وآخر نتيجة، آخر جلسة، الموافقة، «Starts at» (دخولك أم الإقلاع)، وقت إقلاع الجهاز، ومسار سجل الأخطاء.

### الإزالة (Uninstall)

```bash
./main.sh service uninstall   # يوقف (مع الحفظ) ثم يعطّل ويحذف ملف الوحدة؛ تبقى بياناتك
install/uninstall.sh          # الخدمة + مؤقّت التقارير + autostart + أي نسخة يدوية
./main.sh purge --all         # (اختياري) حذف البيانات نفسها
```

### سياسة إعادة التشغيل عند الفشل

| الحالة | السلوك |
|---|---|
| انهيار / `kill -9` / خروج بخطأ | `Restart=on-failure` بعد 5 ثوانٍ؛ ويصلح التعافي الجلسة المقطوعة (`CRASHED`) |
| حلقة المراقبة تجمّدت (لا نبضات) | **watchdog**: بعد `3×INTERVAL_SEC+30` ثانية يقتلها systemd ويعيد تشغيلها |
| فشل متكرر (> 5 مرات في 5 دقائق) | تتوقف الوحدة بحالة `failed` بدل التكرار اللانهائي؛ أصلح السبب ثم `./main.sh service start` |
| إيقاف عادي (`stop`) أو خروج 0 | لا إعادة تشغيل |
| خروج 3 (نسخة أخرى تعمل) أو 4 (لا موافقة) | **لا إعادة تشغيل** (لن تفيد) |
| سُحبت الموافقة | تتخطى systemd الوحدة (`ConditionPathExists`) ولا يُسجَّل شيء |

### أخطاء بدء التشغيل: ملف مستقل

`state/service-error.log` (صلاحيته `600`، يُدوَّر عند تجاوز `LOG_MAX_BYTES`) يستقبل stderr للخدمة فقط؛ الرسائل العادية تذهب إلى journal. مثال: `another instance of the logger is already running (pid 4242): this one exits and will not be restarted`. اعرضه بـ `./main.sh service logs`.

### نسخة واحدة فقط

مرجع الحقيقة قفل `flock` على `state/daemon.lock` يُؤخذ **قبل** لمس أي ملف بيانات؛ يحرّره النواة تلقائيًا إن مات صاحبه (حتى بـ`SIGKILL`) فلا يعلق أبدًا. كل المسارات تمر به: الخدمة، `./main.sh start`، autostart، أو `./main.sh daemon` المباشر. نسخة ثانية تخرج بالرمز 3 دون أن تمس البيانات، و`service start` يرفض البدء ما دامت نسخة يدوية تعمل (ويشرح لك كيف توقفها).

### تعديل الإعدادات

الخدمة لا ترث متغيرات بيئة الصدفة. ضع تعديلاتك (`INTERVAL_SEC`, `MIN_DURATION_SEC`، وحتى `SERVICE_NAME`) في **`config.local.sh`** ثم `./main.sh service restart`. إن غيّرت مسار المشروع أو `INTERVAL_SEC` أعد `./main.sh service install` (ثم `restart`) لتتجدد الوحدة.

### ما اختُبر فعليًا وما لم يُختبر

`tests/test_service.sh` (168 فحصًا) يشغّل **مدير systemd 255 حقيقيًا للمستخدم** (على Ubuntu 24.04) ويجرّب: التثبيت والتفعيل والتشغيل (يعمل مستخدمًا عاديًا لا root، `NoNewPrivs=1`)، `status`، الإيقاف الآمن، `restart`، `kill -9` → إعادة تشغيل تلقائية، تجميد (`SIGSTOP`) → watchdog، حد البدء، النسخة الواحدة (الخدمة/يدوي/مباشر)، غياب الموافقة، سجل الأخطاء، **محاكاة الدخول/الخروج** بإعادة تشغيل مدير المستخدم (مفعّلة → تبدأ وحدها؛ معطّلة → لا تبدأ)، مسار فيه مسافة، والإزالة. وتتأكد الاختبارات من قدرتها على الفشل (حذف `RestartPreventExitStatus` يُسقط ثلاثة فحوص).
**لم يُختبر:** تسجيل دخول رسمي عبر `logind`/PAM وجلسة سطح مكتب رسمية — البيئة حاوية بلا systemd كـPID 1 فشغّلنا مدير المستخدم داخل مساحة أسماء مستقلة. فعلى Ubuntu حقيقية جرّب: `./main.sh service install && ./main.sh service enable` ثم سجّل خروجًا ودخولًا وراجع `./main.sh service status`.

## كيف يعمل (باختصار)

1. كل `INTERVAL_SEC` ثانية يأخذ `collector.sh` لقطة بأمر `ps` (عمليات المستخدم فقط، دون وسائط).
2. `detector.sh` يقارنها بالعمليات المتتبَّعة: الجديد يُسجَّل بدايته، والمختفي تُحسب مدته.
   هوية العملية = `PID + وقت البدء الرتيب`، فلا يخدعه إعادة استخدام PID ولا تغيير الساعة.
3. `storage.sh` يضيف صفًا إلى CSV الشهري (UTF-8 + BOM) عند انتهاء كل عملية؛ و`sessionlog.sh` يسجّل الجلسة في `sessions.csv`.
4. تُحدَّث `heartbeat` و`active.tsv` باستمرار؛ إن مات البرنامج فجأة تُغلق `recovery.sh`
   الجلسة والعمليات المفتوحة عند آخر heartbeat (الحالة `CRASHED` / `POWER_LOSS`).
5. أمر `SIGTERM` (إيقاف/تسجيل خروج/إطفاء) يُغلق كل شيء بشكل نظيف (`COMPLETED`).

### العمليات: `data/processes.csv` + `data/process_details.csv`

**`processes.csv`** — ثمانية أعمدة بالضبط، صف لكل عملية **منتهية** (يُضاف مرة واحدة ولا يُعاد كتابته أبدًا):

| العمود | المعنى |
|---|---|
| `Session_ID` | الجلسة التي رُصدت فيها العملية أول مرة (نفس المعرّف في `sessions.csv`) |
| `PID` · `Process_Name` · `Username` | معرّف العملية، اسمها (comm)، ومالكها |
| `Start_Time` | وقت بدء العملية **الحقيقي** حسب نظام التشغيل (UTC) — صحيح حتى للعمليات التي كانت تعمل قبل المراقبة |
| `End_Time` | وقت **اكتشاف** انتهائها (UTC)، وقد يتأخر حتى فترة فحص واحدة |
| `Duration_Seconds` | `End_Time − Start_Time` دائمًا (محسوبة من الساعة الرتيبة) |
| `Status` | `COMPLETED` رُصدت وهي تنتهي · `SESSION_END` أُوقفت المراقبة نظيفًا وهي تعمل (قد تستمر) · `RECOVERED` ماتت المراقبة ثم وُجدت العملية منتهية عند الإعادة (النهاية = آخر heartbeat، تقدير) |

**`process_details.csv`** — صف مرافق لكل صف، يُربط بالمفتاح `Session_ID + PID + Start_Time`:
`PPID` · `Command_Name` (اسم الملف التنفيذي) · `Class` · `App_Name` · `App_Instance` · `App_Root` · `Started_Before_Session` ·
`Detected_Start` · `Detected_End` (أوقات الاكتشاف الفعلية) · `Paused_Seconds` · `CPU_Seconds` · `Avg_CPU_Percent` · `Peak_RSS_KB` · `Last_RSS_KB` · `Category` · `Start_Epoch` · `End_Epoch`.

**لا نعتمد على PID وحده:** هوية العملية = `PID + وقت البدء الرتيب` (`uptime − etimes`)، فإذا أعاد Linux استخدام PID بوقت بدء مختلف تُغلق القديمة وتُفتح جديدة.

**تطبيق أم عملية خلفية؟** العملية ليست تطبيقًا بالضرورة، والتطبيق قد يكون عشرات العمليات. يُقرَّر `Class` لجذر كل شجرة بالترتيب:
1. `conf/apps.map` (والفئة `background` تُجبره خلفيًا) ← 2. مُشغِّل رسومي `.desktop` ← 3. cgroup (`app.slice` تطبيق · `*.service` خلفية) ← 4. يملك طرفية `pts/N` ← 5. وإلا `Background_Process`.
العملية الابنة تنضم إلى مجموعة أبيها إن كان تطبيقًا (أو يشغّل البرنامج نفسه)، فمتصفح بـ12 عملية = **تشغيل واحد** (`App_Root=yes` مرة واحدة)، ووقته في الإحصاءات = **اتحاد** فترات عملياته لا مجموعها.

**موت المراقب وإعادة تشغيله** — الملفان للإضافة فقط، فلا يضيع أي سجل سابق. العمليات الجارية وقتها محفوظة في `state/active.tsv`، وعند الإعادة:
- ما زال حيًّا (نفس PID ونفس وقت البدء) ← **يُكمَل تتبعه** بسجله الأصلي (نفس الجلسة، نفس وقت البدء الحقيقي)، ولا يُسجَّل «كأنه بدأ الآن».
- انتهى أثناء الغياب ← صف واحد `RECOVERED`.
- سُجِّل صفه قبل الموت لكن لم تُحفظ الحالة ← يُتخطّى (لا تكرار).
- ما يظهر في أول فحص ولم يكن في الحالة ← «وُجد يعمل» (`Started_Before_Session=yes`) لا «بدأ».

أما الإيقاف النظيف (`stop` ثم `start`) فيُغلق العمليات الجارية بحالة `SESSION_END` في الجلسة الأولى، وتظهر في الجلسة الثانية كـ«وُجدت تعمل» — صفان لجلستين مختلفتين، لا تكرار داخل الجلسة الواحدة.

للفحص: `./main.sh processes --check` (يكشف التكرار وكل تلف) · `processes --running` · `processes --apps` · `processes --background`.

### الجلسات: `data/sessions.csv`

ملف واحد لكل الجلسات. يُضاف الصف عند **بداية** الجلسة (`ACTIVE`) ويُحدَّث **نفس الصف** عند نهايتها.
كل الأوقات المخزّنة بتوقيت **UTC**؛ التوقيت المحلي للعرض فقط (`sessions --local` / `--tz`).

| العمود | المعنى |
|---|---|
| `Session_ID` | معرّف فريد، مثل `20261031T113121Z-12529-3e81` (وقت UTC + PID + 4 خانات عشوائية) |
| `Username` · `User_ID` | `whoami` و UID |
| `Login_Date` · `Login_Time` | بداية الجلسة (UTC) |
| `Logout_Date` · `Logout_Time` | نهايتها (UTC) — فارغان أثناء الجلسة |
| `Duration_Seconds` | المدة بالثواني (من الساعة الرتيبة، لا تتأثر بتغيير الوقت). الدقائق تظهر في `sessions` وفي `05_sessions.csv` بالتقرير |
| `Status` | انظر الجدول |

| Status | معناه | وقت النهاية |
|---|---|---|
| `ACTIVE` | الجلسة مفتوحة الآن | — |
| `COMPLETED` | تسجيل خروج / إطفاء طبيعي | وقت الإغلاق |
| `ABORTED` | خرج البرنامج بخطأ لكنه حفظ حالته | وقت الخروج |
| `CRASHED` | مات البرنامج فجأة (`kill -9`…) | آخر heartbeat |
| `POWER_LOSS` | أُعيد تشغيل الجهاز / انقطعت الكهرباء | آخر heartbeat |
| `INTERRUPTED` | صف مفتوح بلا أي معلومة عن نهايته | فارغ |

**الحماية:** كل تعديل تحت `flock` حصري؛ يُكتب إلى ملف مؤقت ثم `mv` ذرّي مع نسخة `sessions.csv.bak`؛
الصف لا يُكرَّر (بدء الجلسة idempotent) ولا يُغلق مرتين؛ السطر الممزّق يُصلَح قبل الإضافة؛
ملف بترويسة غريبة يُنقل إلى `sessions.csv.invalid.<وقت>` ولا يُكتب فوقه؛ ولا يُحذف أي سجل سابق إلا بأمر `purge`.
للفحص: `./main.sh sessions --check`.

### التحليل: Activity Analyzer (`lib/activity.sh`)

يقرأ `sessions.csv` و`processes.csv` و`process_details.csv` **للقراءة فقط** (لا يعدّل البيانات الخام أبدًا، ويثبت ذلك الاختبار بمجاميع sha256) ويحسب بـ `awk` و`sort` و`uniq`.

```bash
./main.sh stats [--from 2026-10-01] [--to 2026-10-31] [--top 10] [--utc-offset +03:00]   # التقرير في الطرفية
./main.sh stats --quality        # ما الذي تُجوهل أو لم يكن اكتمالًا طبيعيًا
```

**ثلاثة مقاييس مختلفة (لا تُخلط):**

| المقياس | معناه | الاستعمال |
|---|---|---|
| **Total Usage Duration** | مجموع مدد الجلسات المغلقة (دخول ← خروج) | «كم استخدمتُ الجهاز» |
| **Active_Seconds** (للتطبيق) | **اتحاد** فترات كل عمليات التطبيق | وقت التطبيق الفعلي؛ عشر عمليات متصفح معًا لساعة = ساعة |
| **Process_Seconds** | **مجموع** مدد العمليات | للشفافية فقط؛ العمليات المتزامنة تتراكم فلا يصلح وقتَ استخدام |

**الاكتمال:** المتوسطات (`Average Process Duration`، متوسط مدة التطبيق) تستخدم عمليات `COMPLETED` فقط. أما `SESSION_END` (حدٌّ أدنى) و`RECOVERED` (نهاية مقدَّرة) فتُحصى وتُذكر في التقرير ولا تدخل المتوسطات. الجلسات `ACTIVE`/`INTERRUPTED` بلا مدة فلا تدخل أي مجموع. إن لم توجد عمليات مكتملة يظهر المتوسط **فارغًا / n/a** لا صفرًا.

**الإطلاق (Launch)** = جذر تطبيق بدأ أثناء المراقبة؛ ما «وُجد يعمل» يُحصى في `Already_Running` لا كإطلاق، ويُقاس وقته من لحظة رؤيته لا من بدئه الحقيقي. العمليات المساعدة (renderers…) تُدمج في تطبيقها؛ وصفوف بلا تفاصيل تبقى `Unknown` ولا تُدمج تخمينًا.

**الأيام:** العدّ (جلسات، عمليات، إطلاقات) في **يوم البدء**، والمدد **تُقسَّم عند منتصف الليل** وتُقصّ على الفترة المطلوبة. `--utc-offset` يحرّك حدود اليوم فقط (المخزَّن يبقى UTC).

**ملفات `report`:** `01_summary` · `02_most_used_applications` · `03_background_processes` · `04_daily_usage` · `05_sessions` (بعدد العمليات لكل جلسة) · `06_process_durations` (مدة كل عملية + هل انتهت طبيعيًا) · `07_data_quality` · `08_report.txt` (التقرير الكامل: Total Sessions / Total Processes / Most Used Applications / Total Usage Duration / Average Process Duration / Daily Usage Statistics).
### مولّد التقارير: Report Generator (`lib/report.sh`)

ثلاثة تقارير CSV جاهزة لـ Excel، تُنتَج **لكل يوم** أو **لأي فترة**:

| الملف | يحوي |
|---|---|
| `session_report.csv` | **Session Report** — صف لكل جلسة: المستخدم، الدخول والخروج (UTC)، المدة بالثواني والدقائق و`HH:MM:SS`، جودة المدة (`EXACT`/`ESTIMATED`/`UNKNOWN`)، وعدد عمليات الجلسة |
| `application_activity_report.csv` | **Application Activity Report** — صف لكل عملية: التطبيق، الفئة (تطبيق/خلفية)، البدء والانتهاء، المدة، الحالة، هل انتهت طبيعيًا، CPU، وملاحظة |
| `usage_summary_report.csv` | **Usage Summary Report** — جدول واحد منتظم: `Overview` (إجمالي الجلسات والعمليات ومدة الاستخدام ومتوسط مدة العملية…) · `Most_Used_Applications` (مرتبة) · `Daily_Session_Time` · `Daily_Application_Active_Time` · `Data_Quality` |
| `report_manifest.csv` | ما كُتب ومتى: لكل ملف عدد الصفوف والحجم وSHA-256 وتاريخ الإنشاء والحالة `FINAL`/`PARTIAL` |

```bash
./main.sh report daily                        # كل الأيام التي فيها نشاط → reports/daily/UTC/YYYY-MM-DD/
./main.sh report daily --date 2026-10-01      # يوم واحد
./main.sh report daily --utc-offset +03:00    # حدود اليوم المحلي → reports/daily/UTC+0300/…
./main.sh report period --from 2026-10-01 --to 2026-10-31 [--name أكتوبر_مثلا]   # فترة → reports/period/UTC/<اسم>/
./main.sh report verify                       # يفحص كل مجموعات التقارير (مانيفست + قواعد Excel)
./main.sh report list                         # المجموعات الموجودة وحالتها
install/install.sh --with-daily-reports       # مؤقّت systemd: تقرير اليوم بعد منتصف الليل (Persistent: يعوّض الأيام الفائتة)
```

**ترتيب ووضوح:** كل ملف يبدأ بعمود `Report_Created_UTC` (تاريخ الإنشاء)، والصفوف مرتبة زمنيًا (الجلسات بالدخول، العمليات بالبدء، الأيام بالتاريخ). الجلسة أو العملية التي تعبر منتصف الليل تظهر في اليومين: `Started_In_Period` يحدد أين بدأت، و`Seconds_In_Period` حصة اليوم منها، فمجموعها يطابق المدة تمامًا.

**عدم استبدال التاريخ دون داعٍ:**
- **`FINAL`** (انتهى اليوم ولا جلسة مفتوحة ولا عملية قيد التتبع قبل نهايته): **مجمَّد** — التشغيل العادي يتخطاه دون حتى إعادة حسابه.
- **`PARTIAL`** (اليوم الجاري، أو فيه جلسة مفتوحة): يُعاد توليده **عند تغيّر المحتوى فقط**؛ لو لم يتغير يبقى كما هو بتاريخ إنشائه الأصلي.
- `--refresh` يعيد حساب يوم نهائي ويستبدله **فقط إن تغيّر محتواه فعلًا**؛ `--force` يعيد كتابته دائمًا. وفي الحالتين تُحفظ النسخة القديمة كما هي في `…/revisions/<وقت-إنشائها>/`.
- سجل تدقيق إضافي فقط: `reports/report_log.csv` (GENERATED / REPLACED).

**الكتابة الآمنة:** مولّد واحد في الوقت (`flock`)؛ البناء في مجلد مؤقت مخفي على نفس القرص؛ كل ملف يُنقل بإعادة تسمية **ذرّية** (القارئ يرى القديم أو الجديد كاملًا، لا نصفًا)؛ والمانيفست آخرًا، فانقطاع في المنتصف يترك مجموعة يكشفها `report verify` ويصلحها التشغيل التالي (وتُنظَّف المجلدات المؤقتة العالقة).

**التوافق مع Excel (يفحصه `report verify`):** UTF-8 مع BOM · نهايات أسطر CRLF · صف عناوين واحد وعدد أعمدة ثابت · اقتباس صحيح (`"Evil, ""App"""`) · تواريخ `YYYY-MM-DD HH:MM:SS` وأرقام عادية · أي اسم يبدأ بـ `= + - @` يُحمى بأبوستروف (لا حقن صيغ) · لا خلية فوق 32,767 حرفًا · لا ملف فوق `REPORT_MAX_ROWS` (افتراضيًا مليون؛ الأطول يُقسَّم إلى `_part1`, `_part2`… بعنوان مكرَّر). وفي الاختبارات تُفتح الملفات فعليًا في LibreOffice للتأكد (أعمدة، أرقام كأرقام، لا صيغ، النص العربي). **لم أستطع تشغيل Excel نفسه** في هذه البيئة.
### فتح التقارير في Excel
افتح ملفات `reports/daily/UTC/<اليوم>/*.csv` مباشرة بنقرتين في Excel. الترميز UTF-8 مع BOM فيظهر العربي صحيحًا،
وأعمدة `*_Seconds` رقمية للجمع والـ Pivot، وأعمدة `*_HMS` للقراءة. (مجموع `Seconds_In_Period` في تقرير جلسات اليوم = استخدام ذلك اليوم.)
إن ظهرت الأعمدة في خلية واحدة (إعدادات إقليمية تستخدم `;`) فاستخدم *Data ▸ From Text/CSV* واختر الفاصل `,`.

## حدود معروفة

- **العمليات الأقصر من فترة الفحص** (تبدأ وتنتهي بين فحصين) لا يمكن رؤيتها بالاستعلام الدوري دون صلاحيات خاصة؛ تُرصد فقط إن صادفها فحص. خفّض `INTERVAL_SEC` في `config.sh` (حتى 1) لالتقاط المزيد.
- `End_Time` وقت **الاكتشاف** (متأخر حتى فترة فحص). `Start_Time` دقته ±1 ثانية (مشتق من «الآن − etimes»).
- القتل بـ`SIGKILL` يُسجَّل `COMPLETED` كأي انتهاء: لا يمكن لمستخدم عادي معرفة سبب انتهاء عملية ليست ابنته.
- CPU/الذاكرة: آخر قيمة رُصدت قبل الانتهاء (CPU = ثوانٍ تراكمية، والذاكرة RSS مع الذروة).
- **الاستهلاك المقاس** (فاصل 5 ثوانٍ، 281 عملية): ‎0.6% CPU و6 MB RAM؛ بفاصل ثانية: ‎2.7% CPU.
- المراقبة لحساب المستخدم الحالي فقط ولا تستخدم `sudo` ولا تقرأ عمليات الآخرين.

- **الدقة:** العمليات الأقصر من `INTERVAL_SEC` قد لا تُلتقط، ووقت الانتهاء هو وقت *اكتشافه* (تأخير حتى فاصل واحد).
- العمليات التي كانت تعمل قبل بدء الجلسة تُوسم `started_before_session=yes`.
- التقارير اليومية تقسّم الجلسات والعمليات العابرة لمنتصف الليل على يومين؛ الإحصاءات اليومية بتوقيت UTC ما لم تُمرَّر `--utc-offset` (إزاحة ثابتة، بلا توقيت صيفي).
- لم تُنفَّذ بعد (انظر `docs/DESIGN.md` §14): ملف `.xlsx` متعدد الأوراق، فاصل `;` للتقارير، تقرير ساعي، مناطق زمنية بالاسم في الإحصاءات اليومية.
